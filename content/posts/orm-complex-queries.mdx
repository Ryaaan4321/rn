# Why I Stopped Using ORMs for Complex Queries

ORMs are great for 80% of use cases. But that remaining 20%? That's where things get interesting.

## The Problem

Last month I was optimizing a reporting dashboard. The query involved:
- 6 table joins
- Window functions for rankings
- Conditional aggregations
- Subqueries for filtering

My ORM-generated query took 4.2 seconds. The raw SQL version? 180ms.

## What Changed

I stopped treating raw SQL as a last resort. Now I use:
- **ORMs** for CRUD, simple joins, rapid prototyping
- **Raw SQL** for reports, analytics, anything with window functions
- **Query builders** (like Kysely) as the middle ground

## The Code

```typescript
// Before: ORM struggling
const results = await prisma.order.findMany({
  include: { user: true, items: true },
  where: { status: 'completed' },
});

// After: Raw SQL winning
const results = await prisma.$queryRaw`
  SELECT 
    u.name,
    COUNT(o.id) as total_orders,
    SUM(o.amount) as total_spent,
    RANK() OVER (ORDER BY SUM(o.amount) DESC) as rank
  FROM users u
  JOIN orders o ON u.id = o.user_id
  WHERE o.status = 'completed'
  GROUP BY u.id, u.name
  HAVING COUNT(o.id) > 5
`;
```

## Bottom Line

Use the right tool. ORMs save time. SQL saves performance. Know when to switch.
